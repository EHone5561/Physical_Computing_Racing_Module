# PiCar 팀 프로젝트

고정된 경기장 규격에서 출발 QR을 읽고 정지선까지 이동한 다음, 양쪽 상자의 물체를 각각 반대쪽 PLACE 상자로 옮기는 프로젝트입니다. 실험으로 구한 서보 각도, 모터 출력, 정지 거리를 `config.json`에 기록해 사용합니다.

**현재 상태: 코드 공유 및 장치별 테스트 준비 단계입니다.** 2026-10-28 기준으로 각도 설정 50개가 `null`이며, 실물에서 전체 미션을 검증하지 않았습니다. `mission.py`는 필요한 라이브러리를 불러온 뒤 `null`을 발견하면 하드웨어 초기화 없이 종료합니다. 아래의 알려진 문제도 전체 미션 실행 전에 검토해야 합니다.

## 파일 구성

```text
.
├── README.md
├── .gitignore
├── picar_team/
│   ├── config.json       # 실험으로 조정할 수치와 하드웨어 설정
│   ├── hw.py             # 서보·모터·초음파·USB 웹캠 제어와 단독 테스트
│   ├── mission.py        # 실제 미션 순서와 QR 판별
│   ├── drive.py          # 미션 1~2만: 출발 QR → 직진 → 정지선 정지
│   ├── drive_centered.py # drive.py + 자이로 직진 보정, 바닥 센서 기록
│   ├── run_all.py        # 명령 하나로 전체 미션 (QR → 보정 주행 → 정지 → 스펀지 두 개 옮기기), `arm left|right`로 팔만 시험
│   ├── practice_logger.py # 시연 JSON 저장과 기록 제어
│   ├── RECORDING.md      # 저장 구조·사용법·변경 내역
│   └── tests/test_recording.py # 가짜 장치로 기록 기능 시험
├── web_monitor/
│   ├── web_status.py     # 기존 웹 조종 프로그램에 추가하는 상태 출력 모듈
│   ├── practice_logger.py # 별도 배포를 위한 동일한 기록기
│   ├── recording.json    # 웹 기록 폴더와 주기
│   └── 사용방법.txt      # 실제 웹서버 확인·적용·로그 보기·복구 방법
├── sim/
│   └── drive_viewer.html # 주행·팔 동작 3D 시뮬레이터 (브라우저로 열기)
└── docs/
    └── GITHUB_UPLOAD.md  # 처음 업로드하거나 기존 팀 저장소에 반영하는 방법
```

이 폴더는 기존 `picar_team`과 `web_monitor`에서 필요한 파일만 복사한 공유용 스냅샷입니다. 기존 폴더와 자동 동기화되지 않습니다. 팀 저장소에 올린 뒤에는 저장소를 내려받은 작업 폴더를 기준으로 수정하고 공유합니다.

강의 PDF, 제조사 전체 배포본, 이전 초안, 압축파일, 실행 캐시는 포함하지 않았습니다. 제조사 웹서버 전체가 들어 있는 저장소가 아니므로, 이 파일만 복사한다고 웹 조종 화면이 설치되지는 않습니다.

## 시연별 기록 기능

미션과 `hw.py` 시험은 실행마다 `practices/practice1.json`, `practice2.json`처럼 새 파일을 만듭니다. 기본 0.1초 주기로 서보·모터 명령, 거리, 경과 시간, 미션 단계를 저장하고 명령 변경 순간도 추가합니다. 시작 당시 설정과 종료 사유를 보존하며, 실험 후 성공 여부와 정지 오차를 추가할 수 있습니다.

웹 조작은 서버를 켜 둔 채 SSH에서 `practice_logger.py start` / `stop`으로 시연을 구분합니다. 기록만 제어하며 로봇을 정지시키는 명령은 아닙니다. 적용 파일이 기존 `web_status.py` 하나에서 기록기·설정까지 세 파일로 늘었습니다. [JSON 기록 사용법과 변경 내역](picar_team/RECORDING.md)을 확인하세요.

## 미션 순서

1. 모니터의 `LEFT` 또는 `RIGHT` QR을 읽습니다.
2. 초음파 거리로 접근 속도를 조절하고 정지 위치를 보정합니다.
3. `hw.lock_wheels()`를 호출해 이후 이 프로그램의 `drive()` 명령을 막습니다.
4. 시작 QR이 지정한 쪽을 먼저 관찰하고 PLACE의 앞/뒤 위치를 기억합니다.
5. 같은 쪽의 PICK 물체를 집습니다.
6. 물체를 든 채 반대쪽을 관찰하고 그쪽 PLACE 위치를 기억합니다.
7. 반대쪽 PLACE에 첫 물체를 놓습니다.
8. 반대쪽 PICK 물체를 집어 처음 기억한 PLACE에 놓습니다.
9. 완료음을 냅니다.

대회 물체 배치는 고정입니다(2026-10-28 확인): 왼쪽 상자는 뒤 칸, 오른쪽 상자는 앞 칸에 물체가 있습니다. 그래서 `look.use_qr`를 `false`로 두어 4·6번에서 팔을 돌려 QR을 읽지 않고 `look.default_place`(왼쪽 PLACE = `front`, 오른쪽 PLACE = `back`)를 바로 씁니다. 배치가 바뀌면 `use_qr`를 `true`로 되돌립니다. 양쪽을 모두 관찰한 뒤 집는 이전 분기는 현재 코드에서 제거되었습니다. `front`는 모니터 쪽 칸, `back`은 출발선 쪽 칸입니다. `left`와 `right`는 주행 방향 기준이며, 카메라 화면의 좌우와 구별해야 합니다. 팔 작업을 위해 차량 자체를 90도 회전시키는 코드가 아니라, 기록한 팔 자세로 좌우 상자를 바라보는 구조입니다.

`lock_wheels()`는 이 프로그램 안의 소프트웨어 잠금입니다. 다른 웹 조종 프로그램의 모터 명령까지 막지는 않습니다.

## 두 가지 사용 방식

| 목적 | 실행하는 프로그램 | 웹 조종 서비스 |
| --- | --- | --- |
| 웹으로 자세를 맞추면서 SSH 로그로 각도 기록 | 기존 제조사 웹서버 + `web_status.py` | 켜 둠 |
| 팀 코드의 서보·모터·거리·QR 테스트 또는 미션 실행 | `picar_team/hw.py` 또는 `mission.py` | 먼저 종료 |

웹 조종과 `hw.py`를 동시에 실행해 상태를 확인하지 않습니다. 두 프로그램이 같은 모터·서보·GPIO를 제어하게 됩니다. 웹 조작 중의 상태는 기존 웹서버 프로세스 안에 붙이는 모니터로 확인합니다.

SSH는 라즈베리파이에 명령을 내리는 접속이고, 브라우저는 그 라즈베리파이가 제공하는 조종 화면을 여는 접속입니다. 같은 Pi에 동시에 연결할 수 있습니다. SSH에는 **현재 노트북에서 접근 가능한 Pi의 IP와 실제 계정명**을 사용합니다. 수업 PDF의 고정 IP는 해당 Pi와 노트북에 그 유선 설정을 적용했을 때 사용하며, 모든 Pi의 기본 주소가 아닙니다. SSH 주소에 `http://`나 웹페이지의 포트 번호를 붙이지 않습니다.

## 먼저 할 일: 웹 조작으로 각도 기록

1. SSH로 접속해 실제 실행 파일과 서비스 이름을 확인합니다.
2. [웹 모니터 사용방법](web_monitor/사용방법.txt)에 따라 `web_status.py`, `practice_logger.py`, `recording.json`을 실제 `WebServer.py` 옆에 복사하고 두 줄을 추가합니다.
3. 해당 서비스가 맞는지 확인한 뒤 재시작하고 로그를 엽니다. 초기화 과정에서 서보가 초기 자세로 움직일 수 있습니다.
4. 웹에서 목표 자세를 맞추고 조작을 멈춘 뒤 `base_cmd`, `arm_cmd`, `wrist_cmd`를 기록합니다.
5. 기록한 값을 `config.json`의 해당 `poses` 항목에 넣습니다. 집게는 `grip.open`, `grip.close`에 따로 기록합니다.

실제 서비스가 `Adeept_Robot.service`인 경우 로그 명령은 다음과 같습니다.

```bash
sudo journalctl -u Adeept_Robot.service -f -o cat
```

로그의 서보 각도는 마지막으로 전달한 **명령 각도**입니다. 실제 관절 각도를 측정한 값이 아닙니다. `speed_setting`은 웹 속도 설정, `M1_cmd`와 `M2_cmd`는 모터 출력 명령이며 실제 이동 속도(cm/s)가 아닙니다. `distance_cm`는 기존 초음파 라이브러리에서 읽은 값입니다. `distance_read_age_s`가 작아도 센서의 새 에코 수신까지 보장하지 않습니다.

모니터는 JSON을 자동 저장하지 않습니다. 로그 보기에서 `Ctrl+C`를 눌러도 로봇은 정지하지 않으며, 로그 보기만 종료됩니다.

## 라즈베리파이 실행 환경

팀 코드는 라즈베리파이에서 실행합니다. Windows에서 Python 문법과 JSON 형식을 확인하는 것과 실제 하드웨어 실행은 별개입니다. 실제 Pi에 설치된 OS, Python 환경, 제조사 프로그램 경로는 현장에서 확인해야 합니다.

| 코드에서 사용하는 모듈 | 필요한 패키지 또는 기능 |
| --- | --- |
| `board`, `busio` | Adafruit Blinka |
| `adafruit_pca9685` | Adafruit CircuitPython PCA9685 |
| `adafruit_motor` | Adafruit CircuitPython Motor |
| `gpiozero` | GPIO Zero와 실제 Pi 환경에 맞는 GPIO 백엔드 |
| `cv2` | OpenCV의 영상 캡처와 `QRCodeDetector.detectAndDecodeMulti()` |
| `json`, `time`, `threading` 등 | Python 표준 라이브러리 |

I2C가 활성화되어 있어야 하며, PCA9685 주소·GPIO 연결·USB 웹캠 번호가 설정과 맞아야 합니다. 검증된 패키지 버전 조합은 아직 기록되지 않아 임의의 버전 고정이나 일괄 설치 스크립트를 포함하지 않았습니다. 우선 제조사 프로그램이 동작하는 Python 환경에서 필요한 모듈의 설치 상태를 확인합니다.

## 장치별 테스트 순서

Pi에 저장소를 내려받거나 복사하고 `picar_team` 폴더에서 실행합니다. 웹에서 움직임을 멈춘 뒤 실제 웹 조종 서비스를 먼저 종료합니다. 서비스 이름이 확인된 경우에만 다음 명령을 사용합니다.

```bash
sudo systemctl stop Adeept_Robot.service
```

| 순서 | 명령 | 확인할 내용 |
| --- | --- | --- |
| 1 | `python3 hw.py dist` | 센서 앞의 실제 거리와 cm 출력 비교 |
| 2 | `python3 hw.py qr` | USB 웹캠으로 LEFT/RIGHT 및 PICK/PLACE 문자열·중심 x좌표 확인 |
| 3 | `python3 hw.py servo` | 서보 이름과 움직임의 대응, 기록한 각도 재현 |
| 4 | `python3 hw.py motor 15 0.2` | 출력 15로 0.2초 작동하는 시험 예시. 전후진 방향과 이동량 확인 |

**각 명령의 이름과 달리 초기화는 공통입니다.** 거리·QR 시험도 모터와 서보 객체를 준비하고 바퀴 정지 및 조향 중앙 명령을 보냅니다. 카메라는 `qr` 시험에서만 엽니다. `hw.py` 단독 테스트는 설정의 모든 `null`을 검사하지 않으므로, `mission.py`의 실행 차단과 혼동하지 않습니다.

`qr` 시험은 인식 결과만 터미널에 출력하며 영상 창은 띄우지 않습니다. `cx`는 화면 가로 방향의 픽셀 좌표이며 실제 상자까지의 거리나 3차원 위치가 아닙니다.

서보 도구에서는 `이름 각도` 형식으로 입력합니다. `p`는 이 도구에서 명령한 `base`·`arm`·`wrist` 값만 JSON 형태로 출력하고, `q`는 종료합니다. 이전 웹 조작에서 사용한 각도를 자동으로 가져오거나 파일에 저장하지 않습니다. 프로그램에서 처음 움직이는 관절은 현재 실제 각도를 모르므로 목표 각도로 바로 이동할 수 있습니다.

각 테스트의 결과를 기록하고 종료한 뒤 다음 테스트를 실행합니다. 웹 조종으로 돌아갈 때에는 팀 프로그램이 종료된 것을 확인한 뒤 서비스를 다시 시작합니다.

## JSON에서 조정할 값

| 항목 | 의미와 조정 목적 |
| --- | --- |
| `pca9685_address`, `servo_channel`, `motor.channels`, `sonar.trig/echo` | 실제 장치 주소와 배선 매핑. 장착이 동일하면 유지 |
| `servo_pulse_us` | 서보 펄스 폭 범위, 단위 µs. 현재 `[500, 2400]` |
| `servo_limits` | 각 관절에 허용할 명령 각도 범위. 목표값은 이 범위로 제한됨 |
| `steer_center` | 직진 조향 기준 명령 각도 |
| `grip.open/close` | 집게를 열고 닫는 명령 각도. 현재 미측정 |
| `poses` | 각 작업 자세의 `base`, `arm`, `wrist` 명령 각도. 현재 미측정 |
| `servo_move_time`, `servo_step_s`, `grip_move_s`, `grip_wait_s` | 관절 이동 시간, 집게를 천천히 여닫는 시간(지금은 확실히 집는 것을 우선해 넉넉하게)과 그 뒤 대기 시간 |
| `motor.direction` | 팀 코드의 전진 명령을 배선 방향에 맞추는 부호. 현재 `-1` |
| `motor.max_speed/slow_speed/fine_speed` | 접근·감속·미세 보정 출력. 실제 속도 단위가 아님 |
| `stop` | 목표 거리·감속 거리·보정 허용 오차와 대기 시간 |
| `sonar.queue_len/max_distance_m` | 초음파 값 평활화 표본 수와 거리 범위 |
| `camera` | USB 웹캠 번호와 요청 해상도 |
| `start_qr` | 출발 QR 연속 확인과 이전 QR 대기 조건 |
| `centering` | `drive_centered.py`의 자이로 주소·부호, 조향 방향, 보정 세기, 바닥 센서 핀 (22·27·17) |
| `run_all` | `run_all.py`의 자이로 사용, wrist 방향 반전(`wrist_flip`), 스펀지를 들고 움직이는 시간, 시작 전 확인 |
| `look` | 상자 QR을 읽을지(`use_qr`), 고정 배치의 PLACE 칸(`default_place`), QR 판별 시도 수와 화면 좌우 해석 기준 |
| `verbose` | 팀 코드의 상태 로그 출력 여부 |
| `recording` | 팀 코드의 시연 JSON 저장 여부, 경로, 표본·파일 갱신 주기 |

현재 미측정 값은 **16개 자세 × 관절 3개 + 집게 2개 = 50개**입니다. 임의로 `0`을 채워 실행 제한을 통과시키지 말고 실제로 확인한 값을 넣습니다. 웹에서 얻은 명령이 `servo_limits` 밖이면 팀 코드가 제한값으로 바꾸므로 같은 자세가 나오지 않습니다.

자세 이름의 의미는 다음과 같습니다.

| 이름 | 사용할 상황 |
| --- | --- |
| `qr_view` | 출발 QR 관찰 |
| `drive` | 주행 중 팔과 센서 방향 유지 |
| `look_left`, `look_right` | 좌우 상자 QR 관찰 (`use_qr`가 `false`면 측정 불필요) |
| `left/right` + `front/back` + `above` | 해당 상자 위에서 접근·들어 올리기 |
| `left/right` + `front/back` + `down` | 해당 상자의 스펀지를 집는 위치 |
| `left/right` + `front/back` + `place` | 해당 상자에 스펀지를 놓는 위치 |

`motor.direction`을 수정해도 제조사 웹 조종의 방향 설정은 바뀌지 않습니다. 정지 목표 30cm 역시 센서 장착 위치와 실제 정지선의 관계를 현장에서 확인해야 합니다.

## 팀이 해결할 중간 목표

| 중간 목표 | 하위 작업 | 확인 기준 |
| --- | --- | --- |
| 1. 접속과 로그 확인 | 실제 Pi 계정·IP·웹서버 경로 확인, 모니터 적용 | 웹으로 한 서보를 조작하면 해당 명령값이 SSH 로그에서 변함 |
| 2. 자세 측정 | 집게 2개 값, 기본 관찰·주행 자세, 네 칸의 접근·집기·놓기 자세 기록 | 각 값의 반복 재현과 이동 경로를 실물로 확인 |
| 3. 상자 판별 확인 | 양쪽에서 두 QR 및 한 QR만 보이는 경우 시험 | `front/back` 판정이 실제 칸과 일치함 |
| 4. 주행과 정지 확인 | 전후진 방향, 출력, 감속·제동·거리 보정 조정 | 반복 시도에서 실제 정지 위치와 센서값을 함께 기록 |
| 5. 전체 미션 연결 | 아래의 알려진 문제 해결, 물체를 든 반대쪽 관찰 확인 | LEFT 시작과 RIGHT 시작 모두 전체 순서를 실물로 검증 |

값을 바꿀 때에는 자세 이름, 변경 전후 값, 성공·실패 상황을 함께 기록합니다. 여러 명이 같은 `config.json`을 동시에 바꿀 때에는 어떤 실험 결과를 반영했는지 커밋 설명에 남깁니다. 물체가 넘어졌을 때 중간부터 재개하는 기능은 현재 포함하지 않습니다.

## 전체 실행 전에 검토할 현재 코드의 문제

다음 동작은 이번 공유 정리에서 수정하지 않았습니다.

- **QR 판별 실패 시 기본 위치로 진행:** `look()`은 모든 시도에 실패해도 `default_place`의 `front`를 반환합니다. 실패했을 때의 중단·재관찰 정책을 정해야 합니다.
- **QR 하나의 위치를 화면 중앙으로 판단:** 두 상자가 화면 한쪽에 몰리면 한 QR만 보이는 경우 앞/뒤를 잘못 판별할 수 있습니다. 실제 관찰 자세에서 확인해야 합니다.
- **정지 보정 실패가 성공처럼 처리됨:** 보정 횟수를 소진해도 오차 범위를 검사해 중단하지 않으며, 마지막 보정 이동 후 새 거리를 확인하지 않고 완료를 출력할 수 있습니다.
- **센서·카메라 대기 조건:** 시작 QR 대기에 시간 제한이 없고 프레임 읽기 실패 시 계속 기다립니다. 초음파의 캐시 값이 실제로 얼마나 최신인지 검증하는 기능도 없습니다.

`null`이 없어졌다는 사실만으로 전체 실행 준비가 끝난 것은 아닙니다. 위 문제와 각 단계 시험을 확인한 뒤 `picar_team` 폴더에서 `python3 mission.py`를 실행합니다.

## 원본 활용과 검증 범위

`hw.py`는 제공된 Adeept PiCar-Pro 코드의 PCA9685·서보 생성 설정, 모터 채널과 출력 방식, GPIO Zero 거리 읽기를 참고합니다. 팀 코드에는 JSON 설정, 이름으로 관절 제어, 자세 보간, 바퀴 잠금, USB 웹캠 QR 읽기, 미션 순서와 테스트 도구를 추가했습니다.

`web_status.py`는 기존 제조사 웹서버에 붙여 성공한 서보 명령을 기록하고 모터·거리 값을 출력하는 별도 보조 코드입니다. 실제 Pi의 `WebServer.py`, `RPIservo.py`, `Move.py`, `Functions.py`, `Ultra.py`가 안내의 구조와 맞는지 확인해야 합니다. Robot HAT을 연결하는 것만으로 이 Python 파일들이 자동 설치되지는 않습니다.

- Python 문법, JSON 파싱과 공유용 복사본 일치를 확인했습니다.
- 웹 모니터는 PC의 가짜 장치 객체로 명령 기록, 출력, 센서 지연·오류, 중복 시작을 시험한 이력이 있습니다. 실물 테스트 결과가 아닙니다.
- GPIO/I2C, 서보 동작 범위, 주행 방향, 카메라 및 실제 경기 성공 여부는 아직 검증되지 않았습니다.
- 시연 JSON 기록을 추가하면서 초기화도 `try/finally` 안으로 옮겨 초기화 오류 때 종료·기록 정리를 하도록 수정했습니다. 미션 순서와 기존 보정값은 유지했습니다.
- 하드웨어 없이 수행하는 기록 기능 테스트 15개를 통과했습니다. 자세한 검증 내용은 `picar_team/RECORDING.md`에 있습니다.

업로드 절차는 [GitHub 업로드 안내](docs/GITHUB_UPLOAD.md)를 참고합니다.
